# 卓盛工具箱 UI、主题、动画与交互优化任务清单（已实施）

日期：2026-10-23。状态：用户已批准实施。T01–T11 已实现，T12 自动与原生宿主验证已通过；Windows 实机显示缩放和安装升级另列验收。完整记录见 docs/UI主题与交互优化-2026-10-23.md。本轮未执行第三方维护操作或发布安装包。

## 目标与建议方向

让普通用户更容易找到工具、读懂用途和影响、知道工具是否运行，并在失败时知道下一步怎么做。视觉建议为“清晰、精致的 Windows 桌面工具箱”：保留紫色品牌主色和现有分类，用中性色建立背景层级，减少装饰干扰，提高字号和交互反馈质量。

建议采用“沿用现有 React + WebView2，逐模块改进”的方案。只换颜色不能覆盖本次逻辑与交互目标；全面重写则扩大回归范围。这里的视觉方向及新增恢复入口均为本次提案，尚未视为用户已批准。

## 本次核对的现状

- 当前项目文件版本为 `1.3.10`，前端使用 React 19、Vite、Lucide；核对依据是源码，未验证当前安装版或线上版本。
- 已有浅色、深色、跟随系统；工具图标、常用工具、双击/Enter 打开、分类搜索与选中项保留。
- 已有“正在打开 / 运行中 / 已退出 / 启动失败”、失败原因和再次打开能力；本次计划增强一致性与恢复操作。
- 系统信息已有缓存和手动刷新；软件合集已有按用途分类、搜索、备用入口与离屏渲染优化。
- 已查看与当前源文件时间相符的本地网页构建预览。预览使用模拟宿主，不代表真实硬件查询、进程管理或维护工具操作通过。
- 当前字号多处为 9–12px，卡片、详情及帮助信息较密；`styles.css`、`improvements.css`、`color-theme.css` 存在同一组件的叠加覆盖。
- 卡片入场目前为 440ms，另有逐项延迟；详情切换重挂载触发动画，登录背景持续旋转。需要统一动效用途与时长。
- `App.jsx` 同时承担会话、导航、主题、启动、文件检查和提醒编排；工具状态采用轮询。旧轮询覆盖新启动结果属于需要构造场景验证的风险，尚未作为已复现缺陷。

- [x] 保留收起侧栏能力，补充收起后的可识别名称和焦点反馈。

主要位置：`App.jsx` 和主布局样式。

验收：1000×700、1366×768、1920×1080 下无非预期横向滚动，详情正文和打开按钮不互相遮挡；125%/150% Windows 缩放另做实际验收。

### T04 · 打磨工具卡片与详情（P1）

- [x] 保留单击查看、双击/Enter 打开，收藏和密码复制独立响应，避免事件冒泡导致误打开。

### T07 · 建立统一动画系统（P1）

- [x] 按钮按下、收藏、复制反馈：约 100–150ms；卡片选中、详情切换：约 150–220ms。
- [x] 侧栏、弹层与主题切换：约 180–280ms；退出比进入略快，快速重复操作可打断。
- [x] 新页面列表可使用一次轻量入场，整组延迟上限 200ms；搜索、轮询及返回列表不反复播放整组动画。
- [x] 工具从“正在打开”到“运行中 / 启动失败”的变化有局部反馈，不移动操作按钮或重排阅读位置。
- [x] 登录背景改为静态或一次短入场；优先采用现有 CSS 与 WebView2 可用能力，主题切换保留兼容回退。
- [x] 跟随系统减少动态效果设置；窗口不可见时停止非必要循环，所有反馈保留可读文字。

主要位置：公共动效样式、卡片、详情、对话框、主题切换及运行状态组件。

验收：动画不阻塞点击和输入，不等待动画完成才执行操作；减少动态效果模式下流程完整；不为基础效果新增大型动画依赖。

### T08 · 统一交互流程与异常恢复（P0）

- [x] 为启动、登录、打开工具、文件检查、复制、外部链接、更新分别写明触发条件、忙碌态、失败与恢复路径。
- [x] 将临时提示分成普通结果与需要处理的错误；需要处理的错误留在当前区域，避免只显示 4.5 秒后消失。
- [x] 错误说明包含发生了什么和下一步；按错误类型连接重试、检查文件、使用说明或日志。
- [x] 完善主题保存失败反馈，区分当前临时显示与已保存偏好；不显示未确认的持久化成功。
- [x] 规范锁定、重新登录和跨页返回时的状态归属，保留现有隐私清空规则。
- [x] 退出软件会结束已启动工具这一行为在现有说明中清晰可见，不新增例行确认弹窗。

主要位置：`App.jsx`、`Login.jsx`、`Dialogs.jsx`、`UtilityPages.jsx`、`useUpdates.js`、`ToolFileCheckPanel.jsx`。

验收：启动提示仍每次宿主启动只确认一次；锁定重登不重复提示。更新取消、失败、重试各有确定行为；不会误把服务不可用显示成最新版本。

### T09 · 加固工具状态和异步顺序（P0）

- [x] 先构造“旧轮询在新启动结果之后返回”、快速切页、锁定重登和请求超时的验证场景。
- [x] 依据验证结果增加请求代次或宿主快照序号，保证新结果不被旧结果覆盖。
- [x] 状态仍以宿主进程树为准，前端启动中的临时状态与宿主快照有明确交接。
- [x] 保留启动去重与必要串行控制，改进忙碌原因，避免让不相关操作看起来无故失效。
- [x] 应用可见时保持及时刷新；隐藏或最小化时降低无效轮询，恢复可见后立即同步；失败后有限退避并可恢复。

主要位置：`useToolStates.js`、`App.jsx`、`WorkbenchController.cs`、`ToolLauncher.cs`；按需求触及 `ToolRunState` 模型。

验收：卡片与详情状态一致；迟到结果不会污染新会话；子进程仍存活时显示运行中；退出清理进程树的既有行为不回归。

### T10 · 整理 React 组件与状态职责（P0，贯穿实施）

- [x] 将应用外壳、侧栏、工具栏、主题切换从 `App.jsx` 分离，应用入口负责组装和路由选择。
- [x] 将启动会话、工具启动、文件检查、提示各自归入明确的 Hook 或局部组件。
- [x] 组合共用按钮、状态提示、空态、对话框的结构；启动提示与驱动提醒使用明确组件，避免累加模式开关。
- [x] 共享状态按功能域组织；仅在兄弟组件确需共享时提升状态，接口区分状态、动作和辅助信息。
- [x] 保留本地 UI 状态，不建立包揽全部业务的大 Context；不为本轮改造引入 Redux 或更换技术栈。

拟新增位置：`frontend/src/components/` 中的外壳及反馈组件、`frontend/src/hooks/` 中的职责 Hook；具体命名在实施时按既有风格统一。

验收：轮询不会导致无关页面整片重渲染；原调用接口和用户行为仍兼容；每次拆分与对应行为测试一同完成。

## 审核后的建议执行顺序

1. T01 固定基线，T08 / T09 确认交互与异步契约，T10 随相关改动整理职责。
2. T02 主题规范 → T03 布局 → T04 / T05 / T06 页面优化。
3. T07 统一动画，T11 补齐键盘与规范；T12 汇总全流程验收。

T04–T06 均以 T02、T03 为前置；T07 依赖稳定布局和明确状态，T12 在所有已批准任务完成后执行。

## 保留的产品约束

- 保留工具入口、原脚本行为、系统重装两项边界、一次启动提示、只读系统信息、更新签名与路径校验。
- 分类筛选和选中项按现有规则保存；锁定后清空敏感会话视图。新增滚动恢复仅限当前解锁会话。
- 不新增批量自动优化、远程控制、自动执行修复或云端账号。
- 本轮测试使用模拟宿主、无害替身及只读操作；涉及真实维护功能的验收沿用隔离环境要求。
- 本清单不更换随包第三方工具，不判定现有安装包安全性；任何后续发布继续遵守项目现有安全与发布门槛。
