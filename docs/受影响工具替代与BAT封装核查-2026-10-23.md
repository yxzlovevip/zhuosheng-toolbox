## BAT 提取结果

ACE 还原版内含 PyInstaller 的 Python 3.13 CArchive。通过只读解析目录、zlib 解压及 xdis 静态读取字节码，提取到：

| 文件 | 原始大小 | 实际作用 |
| --- | --- | --- |
| Disable_hyp.bat | 866 字节 | 关闭 Hypervisor 启动 |
| Disable_vbs.bat | 1250 字节 | 调用 DG Readiness -Disable；条件修改 DeviceGuard/Scenarios 与 WindowsHello 项 |
| Enable_VMX.bat | 1996 字节 | 组合执行 Hypervisor 和 VBS 关闭；**不会开启 BIOS 中的 VMX** |
| DG_Readiness_Tool_v3.6.ps1 | 77648 字节 | Device/Credential Guard 检查与配置；原修复实际调用其完整 -Disable 分支 |

原始 BAT 字节位于 `modules/AceVirtualization/originals/*.bat.txt`；初始提取记录位于 `.build/diagnostics/script-inspection-20261022/ace-extracted-text/extraction.json`。文件以 `.txt` 保留证据，未运行原程序或原始 BAT。

从微软官方下载安装的 `dgreadiness_v3.6.zip` 中，PS1、两个 XML、两个 P7B 和 ReadMe 共 6 个文件与 ACE 提取内容逐字节一致；所用 PS1 的 Microsoft Corporation 数字签名验证通过。官方支持页面列出的适用系统为 Windows 10 / Server 2016，不能据此承诺现代 Windows 11 的完整修复兼容性。

原程序的 3 个 BAT 只是部分功能；已额外读取原主程序的调用关系，核对并保留了四项检测、按结果选择修复、系统信息、BIOS/UEFI 与账户/PIN 提示。未把“提取 3 个 BAT”当作已完整复刻全部功能的唯一依据。

项目原有浏览器清理与 Win10 优化 BAT 已有自有封装，原件哈希仍与其既有记录一致；本次不重写这两项。两个硬件查询 BAT 含 `taskkill WmiPrvSE.exe` 等副作用，不能直接宣传为纯只读封装；现有系统信息的固定只读查询继续保留。

其他二进制中没有提取出可确认完整的明文 BAT，不表示它们不存在脚本，更不表示可以从文件名猜写“原源码”。

## ACE 新封装与明确差异

功能和作用范围逐项见 `modules/AceVirtualization/README.md`。新 EXE 不携带原二进制启动器、Python 运行库或其中的第三方 DLL。微软 DG Readiness 原脚本及完整 `-Disable` 分支按原始字节保留，包括 EFI/BCD、代码完整性策略及相关安全配置的处理，没有换成简化注册表版本。

按照用户此前选择，取消永久修改 CurrentUser 的 PowerShell 执行策略，改为本次子进程参数；管理员权限由 EXE 清单处理。封装增加日志、显式错误和规范退出码，不自动重启。组合修复的前一步失败时会停止并报告，已执行步骤没有自动回滚。这些差异已在模块说明中明列，未更改三项修复功能的目标和命令作用范围。

本地输出：`modules/AceVirtualization/build-output/ACE虚拟化环境检测修复.exe`。

主工程入口仍为 `ace-virtualization`，名称和路径保持原样，总工具数 27。旧文件及旧清单已保存在 `modules/AceVirtualization/test-output/registration.json` 所记录的备份目录中。

本次没有重打其他工作生成的 v1.3.10 主安装器；它不因源目录替换而自动包含本次新模块。后续主安装器必须绑定新的构建和验收记录，不能继续引用旧包哈希作为此次封装的交付证明。
