用户已于 2026-10-23 明确要求自用、全部直接集成；本次不再设置设计或实施确认环节。沿用现有工具目录、完整性检查、运行状态和进程组管理，不替换既有工具。

## 交付范围

- 集成 PowerToys、LocalSend、TrafficMonitor、ShareX、ScreenToGif、QuickLook、BCUninstaller、File Converter 共八个项目。
- 使用官方稳定 Windows x64 发行包，将程序、运行依赖、许可证、来源及哈希一并保留。提取安装包时仅做文件提取，不向当前系统安装或注册扩展。
- 原程序通过工具箱统一入口启动并保留原界面；PowerToys 常用功能增加中文入口。命令行、文件选择或系统集成要求以实际源代码和运行验证为准，不以安装包入口冒充已集成。
- 独立的“效率工具”分类；搜索、收藏、图标、说明、运行状态可用。卸载工具仍归入现有常用工具，网络工具沿用网络分类。
- 工具箱关闭后结束本次启动的工具及其子进程。工具首次启动不自动执行卸载、文件转换或系统修改。
- 打包为新版本本地安装程序，不自动上传服务器、不覆盖用户当前安装。

## 实施步骤

1. 获取并锁定官方发行包，校验 GitHub 提供的 SHA-256，提取到独立目录，记录实际程序和依赖。
2. 先补充集成契约与启动参数测试：八项完整载荷、路径安全、固定参数、依赖变化阻止启动、重复启动和关闭进程组。
3. 完成目录数据、参数与依赖校验支持；为需要文件选择的工具提供小型适配入口，避免空启动不能操作。
4. 接入分类、图标与中文说明，增加界面测试，验证搜索、收藏、说明、启动分发。
5. 对真实程序做无破坏的启动/退出检查；使用临时样本验证适用的文件操作。记录未覆盖的真实设备/跨设备操作。
6. 运行现有相关测试、前端构建、安装包载荷校验，交付安装包和验证记录。

## 重点检查

- 不能仅校验外层适配器而遗漏实际 EXE/DLL；依赖清单应覆盖整个不可变发行载荷。
- 不传递任意前端命令行或任意外部程序路径；入口和参数由内置目录控制。
- 处理单实例原程序退出而后台子进程仍在的情况，不结束用户已有的外部实例。
- 工具配置存放于可写用户目录，不能因 Program Files 不可写导致功能失效。
- PowerToys 和 File Converter 的提取包必须真实可运行；未通过的功能明确记录，不做成功声明。
