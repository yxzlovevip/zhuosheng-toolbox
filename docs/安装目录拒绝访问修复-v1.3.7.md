# 安装目录拒绝访问修复 v1.3.7

日期：2026-10-22。

## 观察与复现

用户运行真实 v1.3.5 安装包时，旧 app 目录替换报“访问被拒绝”。现场检查：管理员身份有效，根目录和 app ACL 为管理员/系统完全控制；所有旧文件独占读写检查通过，未发现残留的安装目录内工具进程。微软 Handle 在检查时未发现相关占用。实际旧目录可以重命名并还原，随后通过原安装器 Main/完整安装流程实际覆盖至 1.3.5 成功。因此不能把最初报错直接认定为永久 ACL 错误，也未捕获到当时具体阻塞进程。

在旧版成品的真实 .NET Framework 引擎中，持有 app/web 子目录的不共享删除句柄，即使普通文件探测全部通过，仍可稳定复现同样的 Directory.InternalMove IOException 和 app 路径拒绝访问。之前只覆盖了安装器自身工作目录，没有覆盖外部子目录句柄短暂存活。

## 修改

旧目录备份、暂存目录发布、备份保留和失败回退的目录重命名，遇到 Windows 错误 5、32、33 时最多等待 15 秒，期间提示正在等待 Windows 释放程序目录。其他错误直接报告。持续失败保留原版本，记录完整异常、路径与工作目录到安装根目录的 install.log，不放宽目录权限或强制关闭外部句柄。

保留 1.3.5 的创建时进程组约束与退出清理逻辑，并合入现有 1.3.6 页面流程/加载优化。1.3.6 安装包保持原样，这次构建为 1.3.7。
