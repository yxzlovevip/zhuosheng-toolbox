# 卓盛工具箱 2.0.0 正式版更新计划

日期：2026-10-24（北京时间）。状态：更新建议，待确认后实施。本轮只核查现状并编写计划，没有修改功能、构建安装包或切换线上版本。

## 1. 版本定位

建议将 2.0.0 定位为“现有功能完整保留、更新修复更顺畅、经过完整安装验收的稳定正式版”。

沿用现有 WPF / WebView2 / React 架构，优先补齐现有使用流程和发布证据。39 个工具入口及现有内置文件默认保留，不重新设计整套界面，不把新增工具数量作为本次目标。任何第三方文件替换都应单独记录来源、功能差异和验证结果，不借版本升级擅自删减工具。

## 3. 必须先处理的发布问题（P0）

### P0-1：为扫描告警形成逐项结论

现有扫描日志对天猫一键重装、技术员一键重装、驱动总裁记录了三项恶意软件规则告警；另外主程序、开源工具适配器和 ScreenToGif 三项为扫描时间超限。扫描时间超限不能等同于发现病毒，也不能记为扫描通过。

此前发布明确按用户要求保留上述工具，2.0.0 计划继续以全部保留为范围；不自动删除、不自动换成其他软件，也不把“用户要求保留”写成“误报已排除”。

- [ ] 冻结待发布工具文件，记录版本、来源、签名、哈希及上次告警。
- [ ] 对规则告警取得可信原件比对、可信扫描及必要的厂商复核证据，逐项记录结论；对超时项目在合适限制下完成复扫。
- [ ] 检查最终安装 EXE 和实际解出的随包文件；保留引擎、病毒库、时间、日志和安装包哈希。
- [ ] 已知感染资源检查继续保留，但不能代替完整扫描。

验收：每项均有“已核清／仍有告警／扫描未完成”的明确结论。无法核清时，应明确报告正式发布仍有未关闭的问题，不能使用“全量杀毒通过”“全部工具安全”等表述。若解决问题需要换文件或调整工具范围，另列具体方案由用户决定，不擅自处理。

### P0-2：补齐 Windows 真实安装、升级与卸载

在独立 Windows 虚拟机或测试机执行，不在用户主机批量运行维护功能。每项系统修改测试前保留可恢复检查点。

- [ ] 首次安装：默认路径、带中文和空格的自定义路径、空间不足、UAC 取消、快捷方式与卸载登记。
- [ ] 运行环境：已有 WebView2；缺少 WebView2 且网络正常；缺少 WebView2 且断网。失败时能说明原因、重试，不能留下错误的安装完成状态。
- [ ] 覆盖升级：1.4.4 → 2.0.0 完整桌面流程；补测仍实际分发的较早版本到 2.0.0。旧版仅在隔离环境使用，不启动历史受影响工具。
- [ ] 保留原安装位置、自定义更新配置和用户文件；核对收藏、主题等用户偏好在升级后的实际行为。
- [ ] 目录暂时占用、权限拒绝、空间不足、安装中断等失败场景：恢复原安装并给出可找到的日志。
- [ ] 卸载仅移除软件拥有的文件，保留额外个人文件；验证重新安装和重启后再次启动。

验收：至少在选定的 Windows 10 x64 和 Windows 11 x64 测试镜像完成流程，记录具体系统版本与补丁。支持范围以测试结果确定，不推定 Windows 7、32 位或 ARM 原生兼容。

### P0-3：完成一次外网客户端整包更新

1.4.4 已有服务器 HTTPS 完整读取和外网分段验证，但记录明确没有完成一次完整外网客户端下载。

- [ ] 从外网测试机通过实际客户端完整下载 2.0.0 候选包，校验长度、SHA-256 和签名清单，再实际安装重启。
- [ ] 验证取消、断网、慢网、重试与损坏包拒绝，临时文件状态正确；失败不冒充“已经是最新版”。
- [ ] 当前更新服务上限为 1,073,741,824 字节（1 GiB），距 1.4.4 仅约 95.5 MiB 余量。构建及发布前增加大小预检，正式包不得超过旧客户端可接受上限。
- [ ] 超过上限时先解决兼容的打包或升级路径，不能仅提高新客户端限制，因为旧版仍会拒绝下载新版。

验收：记录外网完整下载、校验、启动安装器、升级后首次运行四段证据；不得用服务器读取或三个分段替代客户端整包下载。

## 4. 2.0.0 建议交付的使用改进（P1）

| 任务 | 当前不足 | 2.0.0 改动 | 验收标准 |
| --- | --- | --- | --- |
| T01 更新时可继续使用工具 | 宿主在下载和安装两个阶段都要求先关闭工具；下载中也阻止启动 | 分开下载状态与安装交接状态；允许工具运行时下载；安装前列出仍运行的工具名称并引导先保存、退出、重试 | 下载和普通工具使用互不误阻塞；安装交接仍严格等待本次工具进程树退出；不擅自强杀写盘程序 |
| T02 文件损坏有可行修复入口 | 文件检查异常引导到更新页，但服务拒绝同版本下载，最新版损坏后可能仍无从修复 | 增加“重新安装当前版本”独立恢复路径；使用有效签名清单的同版本完整包；复用安装器配置和用户文件保护 | 缺失或变化文件可恢复；占用先重试；过旧清单、未签名包和任意网页传入地址均不能成为恢复来源；正常更新仍拒绝降级 |
| T03 出错后能复制诊断信息 | 已有持续失败提示和日志入口，但日志主要覆盖工具启动 | 增加就近“复制错误摘要”；补记检查更新、下载、校验、安装交接和安装失败的阶段信息，关联安装器日志 | 摘要含软件版本、工具名/阶段、时间和错误；不包含工具密码、令牌、无关硬件标识；锁定后不泄漏上一会话信息 |
| T04 重要影响不用翻找 | 多项影响说明在详情标签页；主按钮旁多为通用提示 | 39 项逐一核对，在主操作附近显示最关键的一句话：是否立即执行、是否删数据、是否改防护、是否需重启 | 浏览器清理明确涉及收藏夹/配置；Win10 优化明确打开后即执行；ACE 不把关闭 Hypervisor 写成开启 BIOS 虚拟化；统一启动提示仍每次程序启动一次 |
| T05 更容易按用途找到工具 | 已可搜索名称、摘要和用途，尚缺统一的别名覆盖 | 为现有工具补充“找大文件、查文件占用、批量改名、传文件、修运行库”等常用表达；搜索覆盖规则与目录一起校验 | 常见中文用途能命中正确工具；收藏继续由独立爱心操作，重启后保留，不因点击爱心打开程序 |
| T06 软件合集入口更清楚 | 222 项已有图标和分类，但集合出处与实际下载来源仍需区分 | 显示官网/作者发布页/网盘/第三方来源及最后核对日期；保留现有入口，失效时给出具体状态；优先人工核对常用入口 | 每项均有来源类型；未经核对显示“待核对”；登录页、网盘验证页和 HTTP 成功不冒充可下载；链接仍由宿主按目录标识解析 |

T06 的逐条深度核查可持续到 2.0.x，但 2.0.0 必须让未核对状态可见，不能宣称 222 项下载及文件均已验证。

## 7. 推荐实施顺序与交付

| 阶段 | 工作与产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：确认基线 | 1.4.4 输入快照、39 项工具保留清单、告警及测试缺口表 | 工作输入稳定，正式版范围明确 |
| B：补齐使用流程 | T01–T05；T06 来源状态与优先入口核对；版本及警告收尾 | 对应失败场景与回归通过 |
| C：冻结候选 | 2.0.0 安装包、载荷清单、哈希、更新说明、扫描记录 | 最终候选来源/扫描结论明确，体积满足旧客户端限制 |
| D：独立验收 | Windows 真安装、覆盖升级、卸载、外网整包、缩放及进程树记录 | 所有必做验收通过，未覆盖边界如实列明 |
| E：正式上线 | 新版本目录、签名清单、校验文件和发布报告 | 先验证版本目录，再切换根清单；上线后实际客户端复查 |

候选可用独立目录的 RC1、RC2 标签区分；现有版本解析只接受数字版本，不能直接将 `2.0.0-rc.1` 填入生产版本字段。最终验收后不再改包；如有改动，重新生成哈希并重跑受影响检查。

开发与常规验收可先按约 5–8 个工作日做粗略排期；这是范围估算，不是发布时间承诺。扫描告警复核、测试机准备和外网下载速度可能延长周期，正式发布日期以验收通过为准。

正式发布继续使用现有 `cz-updates` 路径。先上传并核对 `releases/2.0.0/`，保留上一根清单备份，再原子切换 `latest.json`。已发布目录不覆盖，私钥不上传。核对公网清单签名、整包大小与哈希、实际客户端发现新版/当前版本行为及 Nginx 状态。

服务器切回旧清单只改变更新入口，不会让已升级的 2.0.0 客户端自动降级；已升级客户端的恢复需使用预先验证的安装器回滚或恢复流程。不得把服务器清单回切写成已升级设备完整回滚。
