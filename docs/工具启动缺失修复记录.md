# 工具启动时找不到文件：修复记录

日期：2026-10-21。

## 原因

主程序将清单中的相对路径放在自身目录的 `tools` 文件夹下，例如 `tools/工具/工具/GPU资源占用查看工具.exe`。原始文件存在于项目中，但主程序项目此前只导入了 SMB 模块的内容复制规则。修复前 22 个已登记工具中，21 个未出现在 Debug 运行目录。

本次错误由工具文件未随构建复制导致；没有发现这次错误由安全软件拦截引起的证据。

## 修复

- 在主程序项目中补齐工具目录与重装目录的构建及发布复制规则，保持清单相对路径不变，工具文件放在单文件主程序外的 `tools` 目录。
- 保留 SMB 模块已有的 EXE、配置和说明文件复制规则；不复制暂缓接入的信息查询程序、原 BAT 和用途未确认的 COM 文件。
- 区分文件/目录缺失与其他启动异常，显示缺失的相对路径及完整目录要求。
- 增加真实构建产物的全部清单工具校验，以及缺失目录启动时的错误分类回归测试。
- 界面测试使用独立 Application 加载真实界面样式，避免测试调度窗口事件时误触发生产管理员启动流程；生产权限检查保持原样。

## 已验证

- 原缺失目录回归用例先失败，修复后通过。
- 原全部工具产物校验先报告 21 项缺失，修复后通过。
- 核心测试：23 通过，0 失败。

- 界面测试：10 通过，1 失败。失败项是同期界面工作新增的 `primary button glyphs have readable contrast in both themes`，深色按钮文字对比度为 1.05；此记录不将其算作通过。

没有为验证而执行真实维护工具、导入注册表或进行清理/重装操作。文件齐全和完整性通过不代表第三方工具的内部功能已经验收。

## 使用

退出原来的工具箱，打开 `artifacts/工具箱修复版/CZToolbox.exe`，或重新打开已经修复的 Debug 主程序。主程序需要管理员权限。移动修复版时保留整个目录，不能只复制主程序 EXE。本目录是完整的运行版，不是安装器。
