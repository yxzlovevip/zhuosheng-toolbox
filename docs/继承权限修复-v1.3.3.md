# 继承权限修复 v1.3.3

用户在 1.3.2 选择覆盖 G 盘旧安装并同意修复 `G:\Program Files` 权限后，收到“无法自动修复此目录的权限”。此错误已使用该目录的实际 ACL 只读复现。

## 原因和修改

原实现调用 `SetAccessRuleProtection(true, true)` 后，内存中的继承规则仍标记为继承；`RemoveAccessRuleSpecific` 无法移除这些规则，最终安全检查仍发现原有 Delete 权限。之前测试只构建显式规则，遗漏了实际继承规则。

现在从原始安全描述符复制 ACL，在原始 ACE 上仅收紧非可信主体、非 InheritOnly 的 Allow access mask，设置 DACL 保护标志。保留 ACE 顺序、继承/传播标志、Deny、继承专用 generic mask 以及所有者和组。源对象不变，不使用不能表示 generic mask 的 `FileSystemAccessRule` 构造器重建继承规则。

实盘隔离测试另外发现，直接将 `GetAccessControl()` 取得的未修改对象传回 `SetAccessControl` 时，不会写回任何修改部分，导致权限恢复无效。新增 `ApplyDirectoryPermissions`，明确标记 Access 部分需要写入；修复和失败回退统一使用此函数，保留目录所有者、组和审计规则。
