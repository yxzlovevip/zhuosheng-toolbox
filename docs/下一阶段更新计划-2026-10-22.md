# 卓盛工具箱下一阶段更新计划

日期：2026-10-22。范围：阅读现有软件后提出更新路线，不实施功能修改、系统维护或服务器发布。

## 一、建议方向

先完成安全发布和升级验收，再改善“找到工具、看懂影响、知道是否运行、遇错能处理”的使用流程，最后治理软件合集来源。保留现有功能边界，优先把已有功能做可靠、做容易使用。

本次重新核对：27 项工具源文件与目录清单全部匹配；原工具目录 28 个 PE 文件未检出 EXERESX/KBHKS 资源；v1.3.8 安装包 SHA-256 与构建记录一致。

上述检查不是完整杀毒扫描，也不证明第三方程序的实际操作安全或成功。本轮未重新执行全部测试、未启动维护程序、未做真实覆盖安装。v1.3.8 文档记录的 135 项通过属于此前验证结果。

### 首要发布问题

项目检测报告确认，本地 v1.3.7 安装包的内嵌载荷中有 5 个具有已知感染结构的第三方程序。其 SHA-256 为 `F943AB617B2A2A1EFCEA374F3A62ABAB078C93AFACE8C329251BD4F490635FF5`，与本次读取且签名有效的线上清单所声明哈希一致。本次没有重新下载线上整个安装包；这里确认的是线上清单指向同一哈希的产物。

v1.3.8 已提取还原相关原程序，保留旧文件备份，并加入构建前后资源结构检查。还原文件和通过哈希检查不等于获得可信来源或完成杀毒验收。应首先处理受影响旧包的继续分发问题，再安排合格替代版本发布。

## 三、分批更新

### 第一批：发布安全与升级验收（P0，优先完成）

目标：停止继续提供已确认有问题的产物，建立可核查的替代版本。

1. **处理旧包分发。** 停止提供受影响 v1.3.7 安装包，核对根更新清单、版本下载地址和其他公开入口；保留取证副本与记录，避免直接销毁证据。替代包未验收前，更新服务应明确表示暂不可用，客户端不能误报“已是最新版”。
2. **确认第三方工具来源。** 对受影响的 8 个历史文件逐项核查原厂或可信原件、签名、版本、哈希和扫描结果；无法取得可信原件的项目明确记录处理结论，不能仅重新计算哈希后放行。保留用户要求的工具功能，文件替换必须有依据。
3. **扫描实际发布产物。** 在可信防护环境核查构建环境，对候选安装 EXE 及其实际内嵌文件进行扫描和已知结构检查，记录引擎、病毒库、时间、逐项结论及人工复核。扫描对象必须与最后签名清单声明的安装包相同。
4. **补齐真实升级。** 在隔离 Windows 环境用旧版实际安装，验证自定义路径、旧版退出、更新安装、目录锁重试、失败回滚和重启后启动。不得运行旧包中受影响的第三方工具；旧版夹具限制在隔离环境。
5. **发布材料统一。** 版本号、包哈希、扫描记录、测试结果和更新说明绑定同一产物；发布脚本要求这些验收材料齐全才生成正式发布材料。服务器激活后重新核查公网清单签名和安装包哈希，并阻止受影响旧包继续下载。

验收标准：受影响旧包公开下载已阻止；替代包来源与扫描结论可追溯；真实旧版到新版升级成功，失败场景保持原安装可用；公网清单和下载包与验收产物一致。

版本安排：先评估现有 v1.3.8 是否达到发布门槛；若需修改并重新生成候选包，用新的候选记录追踪。已公开发布的版本目录不得覆盖，变更应提高版本号。

### 第二批：工具状态与故障处理（P1，建议作为下一轮功能更新）

| 更新项 | 现有依据 | 建议改动 | 验收标准 |
| --- | --- | --- | --- |
| 显示运行状态 | 目前启动成功只弹出短暂提示；宿主主要记录启动和失败 | 卡片或详情显示“正在打开、运行中、已退出、启动失败”，按工具标识跟踪已启动实例；对仍在运行的同一工具给出明确提示 | 快速退出、启动失败、持续运行、存在子进程都能正确显示；“已退出”不解释为维护操作成功 |
| 让影响说明更容易看到 | 目录已保存 Risk、Impact、Restart；卡片未显示风险等级，详情底部为通用提示 | 增加简洁的“只读检测／修改系统／可能删除数据”等用途提示；把最关键的具体影响放到打开按钮附近 | 浏览器清理直接说明收藏夹和配置删除；Win10 优化直接说明防护和更新设置变化；保持每次启动只统一提示一次 |
| 检查结果能直接处理 | 文件检查已经支持缺失、变化、无法读取和前往更新 | 从异常项定位工具详情，提供重新检查、查看说明、获取完整安装包等对应操作；同版本损坏可走重新安装路径 | 不会因“已经是最新版”而让用户无路修复；不会把暂时占用误认为必须重装 |
| 错误提示能保留和复制 | 启动异常主要显示 4.5 秒提示；日志只记录工具启动及失败 | 失败信息留在详情，提供复制错误摘要；补充更新检查、下载、安装交接的记录及安装日志位置 | 用户可找到上次失败原因；摘要包含版本和必要错误信息，不收录工具密码或无关设备标识 |
| 更新前说明阻塞原因 | 目前存在受监管工具时，下载及安装都会被阻止，但不列出工具 | 允许在使用工具时下载新版；安装前列出仍运行的工具，要求先保存工作并退出，状态改变后可重试 | 下载与工具启动互不误阻塞；安装仍严格等待工具退出；不自动强制结束可能正在写盘的程序 |

实施顺序：先补宿主的运行状态和错误记录，再接界面；随后完善文件检查的处理入口及更新下载流程。保持关闭工具箱时清理受监管进程的现有规则，并在界面清楚说明这一行为。

### 第三批：查找效率与软件合集质量（P2，第二批稳定后安排）

1. **改善搜索。** 为现有工具加入常用别名和用途关键词，例如“卸载软件、找大文件、测网速、修运行库”。在现有导航中加入常用或最近使用入口，不改变登录后默认显示系统信息的既有行为。
2. **明确合集下载来源。** 将当前“来源于哪个合集”与实际下载来源分开，标明官网、网盘、第三方文件；经过核对的官网入口可优先呈现，其他入口保留明确说明。现有链接类型只区分 share/file/page，不足以证明链接属于官网。
3. **管理链接有效性。** 记录最后核对日期、跳转目标、是否能访问和是否需要人工复核；对 222 款软件分批核对。能打开不等于文件可信、版本适配或可直接下载，登录页与网盘验证页不能简单记为“正常”。
4. **补充适用条件。** 逐项核对 Windows 版本、架构、第三方工具版本和来源；不根据文件名推定兼容性。历史显卡驱动继续单列，避免统一标为推荐。

验收标准：常见中文用途能找到对应工具；合集入口来源清楚，失效链接有处理结论；外部打开继续由宿主使用随包目录中的标识解析，不接受页面传入任意地址。

## 四、贯穿各批的质量检查

- 修复现有安装路径代码的可空性警告，增加明确的路径失败提示，不以压制警告代替处理。
- 回归 1000×700 小窗口、浅深主题、125%/150% Windows 缩放、键盘操作与焦点返回。
- 对系统信息补做实际重启、快速启动和休眠恢复验收；继续显示采集时间，动态数据保持手动刷新及快照语义。
- 把前端、宿主、核心、安装和实际包检查汇总成一次验收记录，区分自动测试、真实安装和第三方工具实际操作。
- 后续涉及代码调整时，只拆分本次改动触及的复杂逻辑，不进行大规模界面重写或全面架构改造。

## 五、本轮明确保留的约束

保留原有工具入口、原 BAT 封装行为、系统重装两项工具的边界、启动时统一提示一次、原安装位置识别及更新签名机制。系统信息继续只读。第三方维护动作不因为工具箱成功启动或进程正常退出而标为“修复成功”。

本计划优先解决已存在的发布和使用问题；暂不安排一键自动优化、远程执行、账号云端化或动态下载后直接运行工具等新产品方向。
