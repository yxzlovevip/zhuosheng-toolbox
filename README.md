# 卓盛工具箱 · Windows 电脑维护工作台

**系统信息、维护工具与软件导航，集中在一个桌面工作台。**

卓盛工具箱面向 Windows 10/11 x64，将分散的维护工具整理为可搜索、可收藏、可查看说明的统一入口。从查看电脑配置、查找常用工具，到了解运行状态与检查文件完整性，为日常装机和电脑维护提供更清楚的操作路径。

`Windows 10 / 11 x64` · `.NET 10` · `WPF + WebView2` · `React + Vite`

[使用说明](docs/使用说明.md) · [开发与构建](docs/构建说明.md) · [更新发布](docs/更新发布说明.md)

> **仓库内容**：项目源码、界面资源、工具清单、构建脚本和测试。第三方工具文件与安装包单独管理，不随仓库分发；完整桌面程序的构建需要另行准备这些文件。

## 从查找工具到了解运行状态

- **按用途查找**：支持分类浏览和用途别名搜索，记不住工具名称也能寻找对应入口。
- **把常用工具放在手边**：收藏经常使用的工具，查看用途、操作步骤和注意事项后再打开。
- **看清当前状态**：区分正在打开、运行中、已退出和启动失败，并提供文件完整性检查。
- **统一日常体验**：提供深浅主题、键盘操作、访问验证与会话锁定，兼顾不同使用习惯。

## 主要功能

| 功能 | 可以做什么 |
| --- | --- |
| 工具工作台 | 分类浏览、用途搜索、收藏、查看详情、启动工具和跟踪进程状态 |
| 系统信息 | 只读查看本机软硬件信息，显示采集时间，支持缓存与手动刷新 |
| 软件导航 | 按分类访问软件网站，查看来源信息与图标 |
| 维护模块 | 提供 SMB 连接诊断、ACE 虚拟化环境检测修复、浏览器清理封装、Windows 10 优化及开源工具适配器 |
| 签名更新 | 验证 RSA 签名清单、安装包大小与 SHA-256，安装前检查工具占用 |
| 安装与恢复 | 支持流式解压、覆盖安装、配置保留、安装事务回滚及按所有权清单卸载 |

工具箱负责组织入口与管理运行过程。工具启动后的维护效果，应在原工具或 Windows 中确认；“已退出”表示进程结束。软件导航提供网站入口，下载和安装由用户自行操作。

## 技术与目录

界面由 React + Vite 构建，通过 WebView2 消息桥调用桌面宿主；核心层负责访问验证、载荷校验、工具进程管理与更新逻辑。

| 路径 | 内容 |
| --- | --- |
| `frontend/` | 界面、消息桥客户端与 Playwright 测试 |
| `src/Toolbox.App/` | WPF/WebView2 宿主、本机信息查询与桥接控制器 |
| `src/Toolbox.Core/` | 工具目录、访问验证、完整性校验、进程管理与更新 |
| `src/Toolbox.Setup/` | 安装、卸载、载荷展开与安装事务 |
| `src/Shared/` | 安装路径与权限策略 |
| `modules/` | 维护模块源码、构建脚本与验证入口 |
| `assets/` | 工具和软件清单、图标、更新公钥与公开更新配置 |
| `scripts/` | 构建打包、资源处理、开源工具获取与签名发布脚本 |
| `tests/` | C#、PowerShell 与 Node 测试 |
| `docs/` | 使用文档、构建说明、设计与历史变更记录 |

## 开始开发

### 准备环境

- Windows x64、Node.js、pnpm 与 .NET 10 SDK。
- 运行桌面界面需要 Microsoft Edge WebView2 Runtime；浏览器测试使用本机 Edge。
- 完整安装包构建还需要 Windows .NET Framework 编译器及工具清单对应的全部文件。

### 构建前端

```powershell
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
```

构建结果输出到 `assets/web/`。运行 `pnpm --dir frontend dev` 可进行界面开发；本机信息查询和工具操作依赖桌面宿主消息桥。

### 运行桌面宿主

先按工具清单准备并审核 `工具/`、`重装/` 下的文件及独立依赖，再运行：

```powershell
dotnet restore src/Toolbox.App/Toolbox.App.csproj
dotnet run --project src/Toolbox.App/Toolbox.App.csproj
```

主程序会申请管理员权限。仅克隆源码时，缺少的工具文件可能影响宿主构建及相应功能。

### 构建完整安装包

完整构建脚本固定使用 `.build/dotnet/dotnet.exe`。准备该路径下的 .NET 10 SDK、全部工具及其依赖后，执行：

```powershell
./scripts/build.ps1 -Version 2.0.0
```

脚本会重建适配器、生成图标与清单、校验工具文件并打包，部分步骤可能联网。详细步骤见 [构建说明](docs/构建说明.md)。历史文档中的旧版本参数请按当前源码核对。

## 测试与验证

按改动范围选择测试。C# 测试通过可执行程序内的断言运行，使用 `dotnet run`。

```powershell
dotnet run --project tests/Toolbox.Tests
dotnet run --project tests/Toolbox.SetupTests
dotnet run --project tests/Toolbox.UpdateFlowTests
node --test tests/SoftwareCollection/source-metadata.test.mjs
pnpm --dir frontend build
pnpm --dir frontend exec playwright test
```

真实宿主登录测试从 `CZ_TEST_PASSWORD` 环境变量读取本机访问口令，请仅在当前测试进程中配置，避免写入仓库或命令日志。前端模拟桥使用独立的 `ui-test-only-password` 测试值。

部分集成测试需要工具文件、安装包、Windows 桌面或管理员权限。浏览器测试使用模拟桥；原生宿主和真实安装需单独验证。涉及清理、系统修复或实际安装的测试有副作用，执行前请阅读对应脚本和模块说明。

## 分发与项目约定

- **源码与成品分开管理**：仓库排除工具二进制、安装包、本地 SDK、依赖缓存和测试输出。
- **私钥单独保管**：`.private/` 与环境凭据不进入仓库。`assets/update-public.pem` 为公开验签公钥；已有客户端使用的密钥需保持匹配。
- **离线工具与联网入口各有条件**：完整离线包需另行准备全部工具及依赖；软件网站访问和缺少 WebView2 时的运行库引导仍需联网。
- **本地访问验证用于会话控制**：不承担服务器端身份认证或机密存储职责。
- **保留第三方许可条件**：第三方工具、脚本和图标归各自权利人所有。仓库目前未附带统一的开源许可证。

当前项目配置版本为 **2.0.0**。历史发布和测试记录以各自记录的环境与时间为准。
