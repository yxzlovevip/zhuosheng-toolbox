# 浏览器配置与推广清理：原 BAT 封装

用户最终选择：直接封装原 BAT，保留全部功能和原执行方式。没有采用此前建议的原生重写、自动备份或安全扫描流程。

## 成品和主软件接入

- EXE：`工具/重装后工具/浏览器配置与推广清理.exe`。
- 主软件入口：重装维护 → 浏览器配置与推广清理（含收藏夹清除）。入口使用主软件已有的高影响操作确认；默认不传静默参数。
- 构建：在项目根目录运行 `modules/BrowserCleanup/build.ps1`。
- 注册或更新入口哈希：运行 `modules/BrowserCleanup/register.ps1`，同时更新模块 `tool-entry.json` 与主软件 `assets/catalog.json`。
- 修改或重建 EXE 后必须重跑注册，否则主软件的完整性校验会拒绝启动。
- 封装为控制台 EXE，使用 Windows .NET Framework 4 系列运行时；成品清单请求管理员权限，主软件已提升时继承管理员权限。

## 原有调用方式

双击 EXE 显示原菜单。`浏览器配置与推广清理.exe /S` 或 `/s` 进入原脚本的模式 2 静默执行；只检查首参数，与原脚本一致。其他普通参数不影响模式；额外文本不拼接进 CMD 命令，避免注入。

BAT 被原字节嵌入 EXE，启动时提取到随机的受限临时目录，校验哈希后交给系统 CMD。保留调用方工作目录、标准输入输出和子进程退出码；退出后只删除提取出的临时脚本及空目录。原始 BAT 文件保持不变。

EXE 的临时路径不能含 `%` 等会被 CMD 重新解析的字符；出现时停止并报错。CMD 的 AutoRun 被禁用，避免执行额外的命令处理器启动脚本。

## 准确影响

原“安全模式”会删除浏览器用户数据和收藏夹；深度模式还清除程序目录及注册表，强制结束进程并修改 IE 主页。固定路径 `D:\Backup\Favorites` 也会删除。

保留原脚本意味着其已知问题仍存在：目录切换失败后相对路径删除可能继续；Edge/EdgeUpdate 策略删除不受模式开关保护；PE 模式没有挂载离线注册表，部分目标仍指向执行环境；“清理完成”没有逐项成功验证。没有自动备份、自动恢复或撤销，使用者须事先手工备份。

原 BAT 的 SHA-256：`A920497432039F668047863973684FD9247DFDE40049BB0B9286A7556498A88B`。构建脚本对该版本固定校验，文件变化时要求重新审查。

## 验证边界

`tests/WrapperTests.ps1` 将同一份封装源码编译为测试 EXE，只内嵌无删除操作的替身 BAT，以验证输入、首参数、工作目录、退出码、资源字节与临时文件清理。

生产 EXE 只做资源、哈希与程序清单检查，不为测试而启动真实清理。不将封装通过等同于真实删除验收、PE 环境验收或目标电脑兼容性验收。

完整审查见 `docs/浏览器清理BAT代码审查.md`。
